# ShopLite

Консольное приложение на C# (.NET 10) с двумя базами данных: реляционной SQLite и нереляционной документной LiteDB. Серверы и Docker не нужны.

## Запуск

```
dotnet run
```

Пакеты скачиваются автоматически, файлы баз `shop.db` и `reviews.db` создаются при первом запуске рядом с программой.

# Отчёт: использование нереляционных баз данных в проекте ShopLite

## 1. Цель работы и задачи

Цель работы: показать на практике, как нереляционная документная база данных LiteDB используется вместе с реляционной SQLite в одном приложении на C#.

Задачи:

1. Разработать консольное приложение «магазин», в котором товары хранятся в реляционной базе, а отзывы покупателей в нереляционной.
2. Реализовать базовые операции с документами: вставку, выборку по индексированному полю, поиск по элементам вложенного массива, удаление.
3. Связать два хранилища на уровне приложения.
4. Оценить преимущества и ограничения выбранного подхода.

## 2. Описание проекта

ShopLite моделирует мини-магазин: в нём есть каталог товаров и отзывы покупателей о них. Приложение управляется из текстового меню. Обе базы встроенные и хранятся в файлах рядом с программой.

Возможности приложения:

- просмотр и добавление товаров;
- добавление отзыва с оценкой от 1 до 5, текстом и тегами;
- просмотр отзывов конкретного товара;
- поиск отзывов по тегу;
- удаление отзыва;
- подсчёт среднего рейтинга по каждому товару.

## 3. Выбор СУБД и обоснование

Данные приложения неоднородны, поэтому для них выбраны разные хранилища.

| Данные | СУБД | Тип | Почему |
|---|---|---|---|
| Товары (название, цена) | SQLite | реляционная | фиксированная структура, первичный ключ, строгие типы |
| Отзывы (автор, оценка, текст, теги) | LiteDB | нереляционная, документная | у отзыва есть вложенный список тегов произвольной длины |

Почему отзывы вынесены в документную базу:

- Отзыв читается и записывается целиком. Теги лежат внутри документа, поэтому не нужна отдельная таблица тегов и таблица связей «многие ко многим», а при чтении не нужны соединения (JOIN).
- Структуру документа можно расширять (например, добавить поле «фотографии» или «ответ продавца») без миграции схемы: старые документы остаются валидными.

Почему именно LiteDB:

- это встроенная NoSQL-СУБД для .NET, которая подключается NuGet-пакетом и хранит все данные в одном файле;
- не требуется устанавливать и запускать сервер, что упрощает развёртывание и проверку работы;
- модель данных документная (внутреннее представление BSON, как в MongoDB), есть индексы и запросы через LINQ.

## 4. Структура проекта

| Файл | Назначение |

| `ShopLite.csproj` | проект .NET 10, пакеты `Microsoft.Data.Sqlite` и `LiteDB` |

| `Program.cs` | текстовое меню и логика, объединяющая два хранилища |

## 5. Модель данных

### Реляционная часть (SQLite)

```sql
CREATE TABLE IF NOT EXISTS Products (
    Id INTEGER PRIMARY KEY AUTOINCREMENT,
    Name TEXT NOT NULL,
    Price REAL NOT NULL
);
```

### Документная часть (LiteDB)

Коллекция `reviews`. Один отзыв хранится как документ:

```json
{
  "_id": 1,
  "ProductId": 2,
  "Author": "Иван",
  "Rating": 5,
  "Text": "Отличная мышь, работает без задержек",
  "Tags": ["беспроводная", "эргономика"],
  "CreatedAt": "2026-10-30T20:00:00"
}
```

Поле `_id` соответствует свойству `Id` класса `Review` и заполняется базой автоматически. Поле `Tags` является вложенным массивом.

## 6. Работа с нереляционной базой

Вся работа с LiteDB собрана в классе `ReviewRepository`.

### Подключение и индекс

```csharp
_db = new LiteDatabase(path);
_reviews = _db.GetCollection<Review>("reviews");
_reviews.EnsureIndex(r => r.ProductId);
```

Файл базы создаётся автоматически. Индекс по `ProductId` ускоряет выборку отзывов конкретного товара.

### Вставка документа

```csharp
public int Add(Review review) => _reviews.Insert(review).AsInt32;
```

Метод возвращает автоматически назначенный идентификатор документа.

### Выборка по индексированному полю

```csharp
public List<Review> GetByProduct(int productId) =>
    _reviews.Find(r => r.ProductId == productId).ToList();
```

### Поиск по элементам вложенного массива

```csharp
public List<Review> FindByTag(string tag) =>
    _reviews.Query().Where(r => r.Tags.Contains(tag)).ToList();
```

Условие проверяет, есть ли нужный тег внутри массива `Tags` документа. В реляционной модели для этого потребовалось бы соединение с таблицей тегов.

### Удаление

```csharp
public bool Delete(int id) => _reviews.Delete(id);
```

### Агрегация рейтингов

Документы читаются из LiteDB, а группировка выполняется в приложении средствами LINQ:

```csharp
var stats = reviews.GetAll()
    .GroupBy(r => r.ProductId)
    .Select(g => (ProductId: g.Key, Avg: g.Average(x => x.Rating), Count: g.Count()))
    .OrderByDescending(s => s.Avg);
```

## 7. Взаимодействие двух хранилищ

Базы между собой не связаны: у LiteDB нет внешних ключей на таблицы SQLite. Связь реализована в приложении через поле `ProductId` в документе-отзыве, которое хранит `Products.Id` из SQLite.

- При добавлении отзыва `Program.cs` проверяет в SQLite, что товар с таким `Id` существует.
- При выводе рейтингов и результатов поиска по тегу название товара по `ProductId` берётся из SQLite.

Следствие: если товар удалить из SQLite, отзывы о нём в LiteDB останутся, поэтому целостность связи обеспечивается кодом приложения, а не СУБД. В проекте удаление товаров не предусмотрено, так что это ограничение не проявляется.

3. Пункт 4: вывести отзывы товара 2.
4. Пункт 5: найти отзывы по тегу `беспроводная`.

## 9. Преимущества и ограничения

Преимущества:

- отзыв с вложенными тегами хранится одним документом, без JOIN и таблиц связей;
- схема документа гибкая, новые поля добавляются без миграций;
- LiteDB не требует сервера: база подключается пакетом и лежит в одном файле;
- запросы пишутся на LINQ, как и остальной код на C#.

Ограничения:

- нет связи между базами на уровне СУБД, целостность поддерживает приложение;
- агрегация рейтингов выполняется в приложении, а не внутри базы;
- встроенная база подходит для небольших приложений, но не рассчитана на высокие нагрузки и работу нескольких серверов, для этого больше подходят серверные решения вроде MongoDB.

## 10. Вывод

В проекте ShopLite реляционная SQLite хранит строго структурированные данные о товарах, а документная LiteDB хранит отзывы с вложенным списком тегов. Для отзывов документная модель оказалась удобнее: теги лежат внутри документа, поиск по ним выполняется без соединений, схема допускает расширение. Реализованы вставка, выборка по индексу, поиск по элементам массива, удаление и агрегация. Связь двух хранилищ обеспечивается в приложении через идентификатор товара. Такой подход подходит, когда основные данные реляционные, а часть информации удобнее хранить в виде документов.
